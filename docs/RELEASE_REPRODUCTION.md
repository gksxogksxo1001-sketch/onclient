# 보안 Agent ‘케셰브’ 최종 릴리스 및 새 환경 재현 기록 (docs/RELEASE_REPRODUCTION.md)

이 문서는 22단계 공식 요구사항에 따라 동일한 최종 단일 소스 커밋을 바탕으로 새 독립 폴더에서 프로젝트를 내려받아 실행하고, 13~21단계의 누적 기능 동작 결과와 데이터 보존 계획, 실제 지원 범위를 정직하게 기록한 문서입니다. (상세 공식 실행 보고서: [docs/NEW_ENV_RUN.md](NEW_ENV_RUN.md))

## 2. 새 폴더 실행 절차 (이동 가능한 상대 경로 기준)

기존 작업 폴더를 그대로 보존한 채, 독립적인 새 빈 폴더에서 저장소를 내려받아 실행하는 절차입니다. 특정 사용자의 로컬 절대 경로에 의존하지 않고 어디서나 실행 가능한 상대 경로(`.`) 기준으로 작성되었습니다.

### 2.1. 새 빈 폴더 준비 및 클론
```powershell
# 1) 작업 대상 외부의 임의 폴더 생성 및 이동
mkdir ./onclient-clean-env
cd ./onclient-clean-env

# 2) 저장소를 새 빈 폴더에 내려받기
git clone -b main https://github.com/gksxogksxo1001-sketch/onclient.git .

# 3) 동일 최종 커밋 확인
git rev-parse HEAD
```

### 2.2. Node.js 런타임 확인 및 환경 설정
```powershell
# 1) Node.js 버전 확인 (Node.js 22~24 환경)
node -v

# 2) 비밀 없는 환경 설정 파일 복사 (기존 폴더 설정 파일 무단 복사 금지)
Copy-Item .env.example .env

# 3) 구문 및 정적 무결성 검사
npm run check
```

### 2.3. 예제 자료(demo) 실행 및 표준 실행 검증
```powershell
# 1) 예제 자료(demo) 모드 실행
npm run demo
# 정상 시작 신호: 콘솔에 "케셰브 예제: http://127.0.0.1:5189" 출력 확인
# 웹 브라우저 접속: http://127.0.0.1:5189

# 2) 서버 종료
# 콘솔에서 Ctrl + C 누르고 Y 입력하여 종료

# 3) 표준 로컬 서버 실행
npm start
# 또는: powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\start-alekov.ps1
# 정상 시작 신호: 콘솔에 "케셰브 연결 확인: http://127.0.0.1:5189" 출력 확인
# 웹 브라우저 접속: http://127.0.0.1:5189

# 4) 종료 후 재실행 무결성 확인
# 다시 Ctrl + C 종료 후 npm start 재실행하여 동일하게 정상 동작함을 확인
```

## 4. 데이터 보존 및 격리 계획 (Data Preservation Plan)

1. **기존 작업 폴더 및 이전 관측 기록 보존**:
   * 기존 작업 폴더는 원형 그대로 영구 보존하며, 재현 시험은 완전히 분리된 새 임의 폴더에서 수행합니다.
   * 새 환경 실행 시 기존 작업 디렉터리의 소스코드, 커밋 이력, 기존 관측 기록을 덮어쓰거나 삭제하지 않습니다.
2. **인증 자격 및 설정 파일 무단 복사 금지**:
   * 기존 폴더에 남아 있는 인증 토큰, 세션 티켓, 로컬 설정(`.env`)을 새 폴더로 무작정 복사하지 않습니다.
   * 새 폴더에서는 `.env.example` 템플릿을 복사하여 독립적으로 구동하며, 무의존성 기본 설정으로 동작함을 보장합니다.
3. **원격 저장점 기반 백업 및 복원 체계**:
   * 모든 변경 사항은 GitHub 원격 저장소(`main` 브랜치)에 단일 최종 커밋으로 푸시되어 영구 보존됩니다.
   * 언제든지 `git clone` 또는 `git checkout <commit-hash>`를 통해 특정 시점의 무결한 상태로 즉각 복원할 수 있습니다.
4. **민감 정보 저장 한계 및 보안 경계**:
   * API 키, 사용자 비밀번호, 개인 인증 자격 등 민감 정보는 Git 저장소 파일 시스템에 평문으로 저장하지 않습니다.
   * 로컬 세션 및 자격 증명은 운영체제 수준의 안전한 보관소(DPAPI helper)에 격리 제어됩니다.

## 5. 남아 있는 UNV(기다림) 목록과 경계

* **17단계 실제 AI 모델 직접 호출**: 로컬 화면 및 계약 상태는 검증 완료되었으나, 외부 유료 상용 AI 모델 직접 호출은 운영 측 게이트웨이 권한 및 자격 준비 대기 상태(UNV)입니다.
* **19단계 실제 원천 조치 집행기 연결**: 화면 계약(요청 접수 ACK와 실제 집행 효과 effectApplied 분리)은 검증 완료되었으나, 실제 기업 망 SDP 엔드포인트 격리 집행기 연결은 운영 측 준비 상태(UNV)입니다.
* **20단계 외부 OSV 라이브 연동**: `package-lock.json` 메타데이터 및 승인 패키지 대조 뷰는 검증 완료되었으나, 외부 실시간 OSV API 통신은 네트워크 승인 대기 상태(UNV)입니다.
* **v1.0 정식 릴리스**: 위 실제 원천 연동 및 22단계 공식 접수 수용 종결 전까지는 `v1.0`으로 단정하지 않고 **검증 중(v1.0 아님)** 상태를 유지합니다.
